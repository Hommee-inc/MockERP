# v0.2 — Commercial core

The first business flow is:

```text
Budget → Sale → Return
```

## Goal

Generate customers, products, budgets, budget items, sales, sale items,
returns, and return items while keeping the relationships explainable.

## Rules

- a sale can only come from a converted budget;
- the sale keeps the budget customer and items;
- sale totals are calculated from sale items;
- a return references an existing sale;
- returned quantity cannot exceed sold quantity;
- return dates are after sale dates;
- the same seed reproduces the same scenario.

## Suggested generation order

```text
customers/products
      ↓
budgets + budget items
      ↓
converted budgets → sales + sale items
      ↓
sales → returns + return items
```

The important design choice is to create dependent records at the moment their
source record is known. A new random customer ID or total should never be
chosen after the fact.

## Tests

The first tests should prove that every sale has a valid customer and converted
budget, every return points to an existing sale item, and no return quantity or
amount exceeds the source sale.

## Portfolio angle

“Built the commercial core of a synthetic ERP with traceable budget-to-sale-to-
return relationships and tests for quantities, totals, and referential
integrity.”
