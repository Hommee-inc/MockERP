# MockERP v1.0 — Plataforma Databricks: Bronze (Guia)

Esta é a primeira versão dentro do Databricks. Se você nunca usou a ferramenta, reserve um tempo só para explorar a interface antes de tentar escrever código.

## O que você vai aprender

O que é a camada Bronze num Lakehouse, o que é uma tabela Delta, e como subir um arquivo Parquet gerado localmente (v0.1 a v0.5) para dentro do Databricks.

## Conceitos para pesquisar antes de começar

- O que é Delta Lake e por que ele é diferente de simplesmente salvar arquivos Parquet numa pasta
- O que é um Volume no Databricks (é onde você vai colocar os arquivos Parquet gerados localmente)
- O que é um Catalog e um Schema dentro do Unity Catalog (a organização `catalog.schema.tabela`)
- Diferença entre rodar um notebook manualmente e uma tabela gerenciada versus externa

## Passo a passo sugerido

1. Dentro do Databricks, crie um Catalog para o projeto (algo como `mockerp`) e dentro dele os schemas `bronze`, `silver` e `gold`
2. Crie um Volume dentro do schema Bronze, é para lá que você vai enviar manualmente os arquivos Parquet da v0.1 a v0.5 (pela própria interface do Databricks, upload de arquivo)
3. Crie um notebook novo e leia um dos arquivos Parquet do Volume usando Spark (pesquise "spark.read.format parquet" na documentação do Databricks)
4. Adicione duas colunas técnicas ao ler o dado: uma com o timestamp de quando a ingestão aconteceu, outra com o nome do arquivo de origem (pesquise `current_timestamp()` e `input_file_name()` em PySpark)
5. Grave o resultado como uma tabela Delta, uma para cada entidade (`bronze.customers`, `bronze.sales`, e assim por diante)

## Ponto de atenção

Não faça nenhuma limpeza ou correção de dado nesta camada, mesmo que você veja um valor claramente errado. O objetivo da Bronze é preservar o dado bruto, do jeito que chegou, incluindo as anomalias da v0.5. A limpeza é trabalho da próxima versão (Silver).

## Como saber se está certo

No Catalog Explorer do Databricks, você deve conseguir navegar até `mockerp.bronze.sales` e ver os dados carregados, com as colunas técnicas de timestamp e origem preenchidas. Rode uma consulta simples (`SELECT COUNT(*) FROM mockerp.bronze.sales`) e confira se o número bate com o que você exportou na v0.1.
