# v0.3 — Inventory

```text
Budget → Sale → Return → Inventory
```

## Goal

Represent stock as a history of movements plus a calculated balance. The
balance must be explainable by the events that changed it.

## Planned entities

- suppliers and purchase entries;
- inventory movements;
- product stock balances.

## Rules

- a sale creates an inventory exit;
- a return creates an inventory entry;
- a purchase creates an inventory entry;
- movement quantities come from their source documents;
- the final balance is calculated in chronological order;
- repeated processing must not create duplicate movements.

## Validation

For each product, sum the initial stock and its movements, then compare the
result with the stored balance. Also verify that every movement can be traced
back to a sale, return, purchase, or explicit adjustment.

## Portfolio angle

“Added traceable inventory movements where sales reduce stock, returns restore
it, and the final balance is derived from the event history.”
