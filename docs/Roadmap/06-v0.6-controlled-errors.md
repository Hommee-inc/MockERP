# v0.6 — Controlled errors

The clean golden dataset remains untouched. This version adds a separate layer
that applies known problems on top of it.

## Planned anomaly types

- duplicate customers or sales;
- missing records;
- invalid foreign keys;
- missing inventory or finance events;
- negative or impossible stock;
- mismatched document totals;
- an evolved schema with an additional field.

Each anomaly should be independently configurable and recorded in a manifest
that identifies the affected record and the expected issue.

## Why keep this separate?

If broken data is generated inside the normal entity generators, there is no
reliable clean baseline for comparison. Separating generation from anomaly
injection makes the quality pipeline measurable.

## Portfolio angle

“Introduced reproducible, documented data-quality issues on top of a clean ERP
dataset so detection and remediation pipelines could be measured.”
